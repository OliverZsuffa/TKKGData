# Documentation

## Start here
1. Project instructions define the engineering rules and approval workflow.
2. The knowledge base contains reusable architecture and verified lessons.
3. Approved decisions records decisions explicitly approved by Oliver.
4. Requests explains the request and implementation workflow.

## Sources of truth
- The approved request defines scope and acceptance criteria.
- Its approved implementation-plan.md defines the intended implementation.
- Current code and validated source evidence describe actual behaviour.
- docs/decisions.md contains explicitly approved durable decisions.
- Request notes contain actual test results, implementation status, and unresolved work.

Do not treat an unapproved proposal or an inferred detail as a confirmed requirement.
